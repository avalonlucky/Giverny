# Agent Enterprise Roadmap

本路线图用于把 Giverny 工作助手从“受控业务助手”建设为可审计、可恢复、可代替人工执行日常工作的企业级 Agent。每次 Agent 正式发布都要同步更新状态，不以模型宣传代替工程验收。

## 优先路线

| 序号 | 建设方向 | 状态 | 当前进展 | 完成标准 |
| --- | --- | --- | --- | --- |
| 1 | 最终答案逐字段验真 | 已完成 | AliceAgent、Worker 兼容链路和全部业务读取工具共用结构化事实协议；生产健康检查持续验证正确摘要、来源覆盖与错误事实拒绝 | 已达成：业务正文由程序按工具证据生成，发布后生产自检为强制门禁 |
| 2 | 无 Wrangler 全链路质量门 | 已完成 | 本机与 CI 共用 Miniflare workerd 隔离运行时，每个分片创建临时 D1/R2/DO/Workflow；正式发布使用 HTTP API Direct Upload | 已达成：工具链、浏览器和 CI 无 Wrangler，覆盖真实写入、幂等、失败重试、workerd 重启恢复与强制清理 |
| 3 | 统一 Agent 能力注册表 | 已完成 | 82 项读取、项目执行、批量事务、计划编辑与续接、全域搜索、一致性审计、正式交付物、高风险治理、安全诊断与恢复、任务记忆、企业分层记忆、结算、Agenda、排期、附件、多模态分析、主动事项、提醒、后台分析、写入预览、签名执行和内部 Workflow 能力统一登记；Alice、Worker、MCP、OpenAPI 与 Workflow 共用 | 已达成：schema、角色、scope、风险、确认关系、审计事件、轨迹、文档和测试均由同一注册表生成 |
| 4 | 权限与租户安全加固 | 已完成 | HMAC scope 使用常量时间校验，模型工具按角色裁剪；任务/搜索/附件/分享链接/确认凭证均绑定工作区，提示注入进入不可信数据边界 | 已达成：跨租户 ID、模糊搜索、附件元数据与路径、匿名枚举、提示注入、凭证错租户/错主体/篡改/换动作/重放攻击全部通过隔离门禁 |
| 5 | 多步骤任务执行引擎 | 已完成 | 执行批次具备 DAG 步骤依赖、整体确认、失败即停、重试、暂停/恢复、反向补偿、乐观并发控制与跨会话 D1 恢复 | 已达成：未确认批次不可推进，Workflow 结果确定性回写，失败阻断下游，补偿只允许调用已注册安全工具，隔离环境覆盖完整状态迁移 |
| 6 | 补齐业务操作工具 | 已完成 | 新增结算记录查询/核对/导出/锁定/分享有效期/未锁定删除、Agenda 总览/空闲建议、排期冲突/调整、附件直传接力、站内提醒、模型设置检查/测试/配置共 17 项能力；5 组真实写入全部走签名确认与 Workflow | 已达成：高频人工操作均有明确工具、角色与 scope、确认、幂等、审计、事实协议和隔离回归 |
| 7 | 文件与多模态工作流 | 已完成 | 安全上传接力、任务关联、OCR/PDF/表格证据读取、分析状态查询/失败重试、附件元数据与对外可见性修改均进入统一工具链；XLSX 保留工作表、单元格和值 | 已达成：附件内容结论带稳定证据引用，客户权限过滤、扩展名保护、结算锁定、乐观并发和 Workflow 隔离回归全部通过 |
| 8 | 主动工作能力 | 已完成 | 任务创建/修改/附件上传后即时计算风险，Cron 兜底扫描；逾期、临期、等待、工时超估、100% 待验收和验收备注缺口进入独立主动事项队列 | 已达成：事件证据、四级优先级、建议动作、源版本去重、解决/忽略/稍后处理、自动闭环和处理效果统计全部落库并通过隔离回归 |
| 9 | 企业知识与记忆系统 | 已完成 | 组织规则、合作伙伴记忆、项目记忆统一落库；任务记忆、个人知识笔记和产品知识保持清晰边界 | 已达成：来源、置信状态、有效期、版本链、纠正、失效、软删除、租户隔离、确认 Workflow 和任务中心管理全部通过门禁 |
| 10 | 集成、SLO 与治理 | 已完成 | 五项生产 SLO 进入运行中心与发布门禁；主模型先同模型重试，回退按明确故障分类审计；HTTP API 候选版本定向验收，失败自动恢复上一版本；签名运行告警连接器不发送业务正文 | 已达成：99% 主模型目标、100% 事实验真、错误预算、候选冒烟、自动回滚、签名外部事件和确定性治理测试全部落地 |

## 首批新能力

| 序号 | 能力 | 状态 | 当前进展 |
| --- | --- | --- | --- |
| 1 | 结算 Agent | 已完成 | 可查询并交付历史回单的在线预览、分享、Excel、PDF；按任意日期范围生成确定性快照；逐行复算任务数、工时、金额与小计，识别重复任务、快照变化、日期重叠和空档；确认后可锁定、调整有效期或删除未锁定记录。预览后数据变化会拒绝旧凭证，锁定记录删除仍只允许在管理界面验证管理员密码 |
| 2 | 文件 Agent | 已完成 | 支持搜索、预览、安全上传接力、OCR/PDF/XLSX 证据读取、分析状态查询与失败重试，以及确认后修改名称、标签、范围和合作伙伴可见性；浏览器直传 R2，API Key 不进入模型 |
| 3 | 日程 Agent（Agenda） | 已完成 | 支持今天/本周/任意 63 天内的任务、到期风险、活动等待、站内提醒和每日负载总览；按工作时段、任务时长、步长与周末偏好给出未来可用时间候选；明确开始时刻的任务复用日历“开始时间 + 预估工时”占用规则，跨日计划不误判为全天忙碌。排期预览绑定任务旧状态和冲突快照，确认期间发生变化会拒绝旧凭证，结算锁定月份仍拒绝修改 |
| 4 | 项目执行 Agent | 已完成 | 除创建、反馈、进展、等待、记录维护、验收、排期、提醒和 DAG 依赖/补偿编排外，现可确定性查询计划当前步骤、下一步、失败步骤与依赖阻塞，并关联任务状态、活动等待、站内提醒和主动风险；暂停、恢复、失败步骤重试和取消全部经过预览、签名确认、版本校验、幂等 Workflow 与审计。Agent 不具备直接完成业务步骤的工具，只有真实业务写入成功才能推进计划 |
| 5 | 安全设置 Agent | 已完成 | 可一次性诊断当前首选模型与文字/识图四路主备链路，核对凭证来源、连接结果、近期回退原因和策略合规性，明确 99% 主模型目标、同模型先重试和修复顺序；配置前验证服务商/Base URL/模型，确认凭证绑定完整路由快照，确认期间变化会拒绝旧操作。每次修改前自动保存不含密钥的历史版本，可确认后恢复上一份配置；恢复前再次验证文字主模型。API Key 不接受模型输入、不进入快照/确认卡/审计正文，也不返回 |
| 6 | 沟通 Agent | 站内提醒已完成 | 可确认后创建任务中心定时提醒；飞书、邮件和外部日历的确认后发送仍未开始 |

## 发布纪律

- 每轮至少推进一项可验证能力，不用新增文案代替实现。
- 所有业务事实必须来自确定性工具；模型只负责理解、规划和表达。
- 所有写入继续遵循预览、确认、幂等执行、审计和失败恢复。
- 用户选择的主模型是正常路径；只有极端故障才允许启用备用模型，并明确记录原因。
- 不使用 Wrangler。正式部署与后续隔离评测统一迁移到 Cloudflare HTTP API。
- 不修改金额、工时、验收日期或结算口径，除非用户明确提出对应业务变更。
