# Agent Enterprise Roadmap

本路线图用于把 Giverny 工作助手从“受控业务助手”建设为可审计、可恢复、可代替人工执行日常工作的企业级 Agent。每次 Agent 正式发布都要同步更新状态，不以模型宣传代替工程验收。

## 优先路线

| 序号 | 建设方向 | 状态 | 当前进展 | 完成标准 |
| --- | --- | --- | --- | --- |
| 1 | 最终答案逐字段验真 | 已完成 | AliceAgent、Worker 兼容链路和全部业务读取工具共用结构化事实协议；生产健康检查持续验证正确摘要、来源覆盖与错误事实拒绝 | 已达成：业务正文由程序按工具证据生成，发布后生产自检为强制门禁 |
| 2 | 无 Wrangler 全链路质量门 | 已完成 | 本机与 CI 共用 Miniflare workerd 隔离运行时，每个分片创建临时 D1/R2/DO/Workflow；正式发布使用 HTTP API Direct Upload | 已达成：工具链、浏览器和 CI 无 Wrangler，覆盖真实写入、幂等、失败重试、workerd 重启恢复与强制清理 |
| 3 | 统一 Agent 能力注册表 | 已完成 | 50 项读取、计划、记忆、结算、排期、附件、提醒、安全设置、后台分析、写入预览、签名执行和内部 Workflow 能力统一登记；Alice、Worker、MCP、OpenAPI 与 Workflow 共用 | 已达成：schema、角色、scope、风险、确认关系、审计事件、轨迹、文档和测试均由同一注册表生成 |
| 4 | 权限与租户安全加固 | 已完成 | HMAC scope 使用常量时间校验，模型工具按角色裁剪；任务/搜索/附件/分享链接/确认凭证均绑定工作区，提示注入进入不可信数据边界 | 已达成：跨租户 ID、模糊搜索、附件元数据与路径、匿名枚举、提示注入、凭证错租户/错主体/篡改/换动作/重放攻击全部通过隔离门禁 |
| 5 | 多步骤任务执行引擎 | 已完成 | 执行批次具备 DAG 步骤依赖、整体确认、失败即停、重试、暂停/恢复、反向补偿、乐观并发控制与跨会话 D1 恢复 | 已达成：未确认批次不可推进，Workflow 结果确定性回写，失败阻断下游，补偿只允许调用已注册安全工具，隔离环境覆盖完整状态迁移 |
| 6 | 补齐业务操作工具 | 已完成 | 新增结算记录查询/导出/锁定/分享有效期、排期冲突/调整、附件直传接力、站内提醒、模型设置检查/测试/配置共 15 项能力；5 组真实写入全部走签名确认与 Workflow | 已达成：高频人工操作均有明确工具、角色与 scope、确认、幂等、审计、事实协议和隔离回归 |
| 7 | 文件与多模态工作流 | 核心已具备 | 已有附件搜索、预览、后台分析和浏览器到 R2 的安全上传接力；后续补强跨格式批处理与失败恢复 | 支持安全上传接力、任务关联、OCR/PDF/表格理解、证据引用和失败恢复 |
| 8 | 主动工作能力 | 核心已具备 | 已有周期复盘、风险提醒、任务中心和可由 Agent 确认后创建的定时站内提醒 | 支持事件驱动待办、优先级、处理建议、去重和处理效果统计 |
| 9 | 企业知识与记忆系统 | 基础已具备 | 已有任务记忆、产品知识和人工纠正 | 增加项目、合作伙伴、组织规则分层记忆，全部支持来源、失效、纠正和删除 |
| 10 | 集成、SLO 与治理 | 基础已具备 | 已有运行指标、失败指纹和主备模型记录 | 接入外部系统，建立可执行 SLO、发布金丝雀、自动回滚与严格备用模型策略 |

## 首批新能力

| 序号 | 能力 | 状态 | 当前进展 |
| --- | --- | --- | --- |
| 1 | 结算 Agent | 核心已完成 | 可查询历史导出，按任意日期范围生成确定性回单快照、Excel 与分享链接，并确认后锁定或调整链接有效期；预览到执行之间数据变化会拒绝旧凭证 |
| 2 | 文件 Agent | 核心已完成 | 支持搜索、预览、分析和安全上传接力；Agent 只解析任务归属和文件元数据，二进制由已登录浏览器直传 R2，API Key 不进入模型 |
| 3 | 日程 Agent | 核心已完成 | 支持排期冲突查询与任务开始、交付、预估工时的确认后调整；结算锁定月份仍拒绝修改 |
| 4 | 项目执行 Agent | 核心已完成 | 已覆盖创建、反馈、进展、等待、记录维护、验收、排期、提醒和多步骤依赖/补偿编排 |
| 5 | 安全设置 Agent | 核心已完成 | 可脱敏检查四路模型、测试已保存凭证对应的路由，并确认后配置服务商/Base URL/模型；API Key 不接受模型输入也不返回 |
| 6 | 沟通 Agent | 站内提醒已完成 | 可确认后创建任务中心定时提醒；飞书、邮件和外部日历的确认后发送仍未开始 |

## 发布纪律

- 每轮至少推进一项可验证能力，不用新增文案代替实现。
- 所有业务事实必须来自确定性工具；模型只负责理解、规划和表达。
- 所有写入继续遵循预览、确认、幂等执行、审计和失败恢复。
- 用户选择的主模型是正常路径；只有极端故障才允许启用备用模型，并明确记录原因。
- 不使用 Wrangler。正式部署与后续隔离评测统一迁移到 Cloudflare HTTP API。
- 不修改金额、工时、验收日期或结算口径，除非用户明确提出对应业务变更。
