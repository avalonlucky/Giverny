# Agent Enterprise Roadmap

本路线图用于把 Giverny 工作助手从“受控业务助手”建设为可审计、可恢复、可代替人工执行日常工作的企业级 Agent。每次 Agent 正式发布都要同步更新状态，不以模型宣传代替工程验收。

## 优先路线

| 序号 | 建设方向 | 状态 | 当前进展 | 完成标准 |
| --- | --- | --- | --- | --- |
| 1 | 最终答案逐字段验真 | 进行中 | 已完成金额、工时、百分比、日期、状态、任务 ID、任务/附件数量的事实快照、错误拦截和确定性摘要 | 所有业务回答均使用结构化事实协议；受控在线评测无错误关键事实 |
| 2 | 无 Wrangler 全链路质量门 | 未开始 | 已确认现有隔离与浏览器评测仍依赖 Wrangler | CI 和本机使用 HTTP API Direct Upload + 临时 D1/R2/Worker，覆盖真实写入与恢复 |
| 3 | 统一 Agent 能力注册表 | 未开始 | 读取工具已有共享注册表，写入和后台任务仍散落在 Runtime | 工具 schema、权限、风险、确认、审计、文档和测试从同一注册表生成 |
| 4 | 权限与租户安全加固 | 基础已具备 | 已有工作区签名、角色边界和 D1/R2 过滤 | 跨租户 ID、模糊搜索、附件路径、提示注入和确认凭证攻击测试全部通过 |
| 5 | 多步骤任务执行引擎 | 基础已具备 | 已有持续计划、Workflow、单操作幂等与恢复 | 支持步骤依赖、批次确认、失败停止、补偿/回滚、暂停和跨会话恢复 |
| 6 | 补齐业务操作工具 | 未开始 | 已覆盖任务生命周期，结算、日程、上传、通知和安全设置尚未统一开放 | 高频人工操作均有明确工具、权限、确认和审计 |
| 7 | 文件与多模态工作流 | 基础已具备 | 已有附件搜索、预览和后台分析 | 支持安全上传接力、任务关联、OCR/PDF/表格理解、证据引用和失败恢复 |
| 8 | 主动工作能力 | 基础已具备 | 已有周期复盘、风险提醒和任务中心 | 支持事件驱动待办、优先级、处理建议、去重和处理效果统计 |
| 9 | 企业知识与记忆系统 | 基础已具备 | 已有任务记忆、产品知识和人工纠正 | 增加项目、合作伙伴、组织规则分层记忆，全部支持来源、失效、纠正和删除 |
| 10 | 集成、SLO 与治理 | 基础已具备 | 已有运行指标、失败指纹和主备模型记录 | 接入外部系统，建立可执行 SLO、发布金丝雀、自动回滚与严格备用模型策略 |

## 首批新能力

| 序号 | 能力 | 状态 | 当前进展 |
| --- | --- | --- | --- |
| 1 | 结算 Agent | 未开始 | 网站已有结算导出，AliceAgent 尚未拥有统一的导出、分享和下载工具 |
| 2 | 文件 Agent | 基础已具备 | 已支持搜索、预览和分析，缺少安全上传接力与完整文件操作编排 |
| 3 | 日程 Agent | 未开始 | 已有时间字段和语音识别，尚无冲突检查、排期和日历操作工具 |
| 4 | 项目执行 Agent | 基础已具备 | 已能创建、反馈、进展、等待和验收，缺少多步骤事务与自动补偿 |
| 5 | 安全设置 Agent | 未开始 | 已能回答设置方法，尚不能通过安全表单接力配置或验证模型账户 |
| 6 | 沟通 Agent | 未开始 | 尚未接入飞书、邮件和日历的确认后发送能力 |

## 发布纪律

- 每轮至少推进一项可验证能力，不用新增文案代替实现。
- 所有业务事实必须来自确定性工具；模型只负责理解、规划和表达。
- 所有写入继续遵循预览、确认、幂等执行、审计和失败恢复。
- 用户选择的主模型是正常路径；只有极端故障才允许启用备用模型，并明确记录原因。
- 不使用 Wrangler。正式部署与后续隔离评测统一迁移到 Cloudflare HTTP API。
- 不修改金额、工时、验收日期或结算口径，除非用户明确提出对应业务变更。
