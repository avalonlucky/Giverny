# Agent 企业知识与记忆

Giverny 将长期上下文分为四类，避免把模型猜测、任务事实和人工规则混在一起：

1. **任务记忆**：由任务详情、进展和等待记录自动压缩，只服务于单个任务，任务原始数据始终是权威来源。
2. **企业分层记忆**：组织规则、合作伙伴记忆、项目记忆，必须携带来源说明、版本和有效期。
3. **个人知识笔记**：管理员自行整理的参考资料，按工作区隔离，不等同于已确认业务事实。
4. **产品知识**：由仓库手册和更新日志构建的只读索引，用于回答 Giverny 产品使用与品牌问题。

## 分层与类型

- `organization`：适用于当前工作区的统一规则，例如验收结论必须引用任务与附件事实。
- `partner`：某个合作伙伴的长期偏好、约定和已确认事实，必须填写合作伙伴名称。
- `project`：跨任务延续的项目约定、决策和背景，必须填写项目名称。
- 记忆类型分为事实、偏好、规则和决策；类型只帮助检索，不改变权限。

## 来源与有效期

每条记忆必须填写来源说明，可补充任务、对话、文档引用和原文摘要。人工确认内容标记为 `confirmed`；程序或模型推导只能标记为 `derived`，回答时不得把推导内容表述为人工确认事实。

记忆可以长期有效，也可以设置到期时间。到期记录自动退出默认查询；历史视图仍可查看。任务中心可主动设为失效，不需要等待到期。

## 纠正与删除

- 纠正不会覆盖旧记录：旧版本进入 `superseded`，新版本递增版本号并保存 `supersedes_id`。
- 失效保留正文和修订记录，但默认查询不再引用。
- 删除使用软删除；默认查询不可见，历史和审计仍保留。
- Agent 维护记忆必须经过预览、人工确认、签名凭证和 Workflow。确认前若原记录已变化，旧凭证会被拒绝。

## 权限与租户

所有记忆、修订和个人知识笔记都按 `workspace_id` 隔离。管理员和协作者可维护企业记忆；只读成员与 MCP 可查询；合作伙伴、访客不可读取内部企业记忆。模型不会获得数据库凭证，只能调用当前身份允许的确定性工具。

## 操作入口

在工作助手中打开“记录与任务 → 后台任务 → 企业记忆”，可以按组织、合作伙伴和项目筛选，新增、纠正、失效或删除记录。也可以直接对 Agent 说“记住这条组织规则”或“纠正某条合作伙伴记忆”，系统会先给出确认卡。
