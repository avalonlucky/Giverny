# Agent Orchestrator

## 定位

Giverny Agent 不把大模型直接等同于产品。大模型负责理解、规划和语言组织；Agent 编排层负责权限、工具、业务规则、证据、确认、重试和结果验真。

统一链路：

```text
用户请求
  -> AgentTurn（租户、身份、会话、本轮目标）
  -> 理解意图
  -> 生成计划
  -> 权限与风险授权
  -> 调用 D1 / R2 / 产品注册表 / 知识库工具
  -> 模型分析
  -> 确定性验真
  -> 证据不足或工具失败则动态重规划（最多三轮）
  -> 仍不满足则停止或追问，不编造业务结论
  -> 写入动作进入预览与人工确认
  -> 最终回答
```

## 核心契约

`src/agentOrchestrator.ts` 定义统一 `AgentTurn`：

- `principal`：工作区、登录主体、角色、本轮运行 ID。
- `intent`：财务、任务、附件、产品帮助、知识、写入或普通问答。
- `plan`：模型提出的工具调用计划及理由。
- `evidence`：工具返回的结构化证据，标明来源和是否可确定性校验。
- `verification`：业务结论是否有足够证据、缺少哪些工具、是否需要继续执行。
- `phase`：理解、计划、授权、执行、分析、验真、完成、待补充或失败。
- `status`：每个工具调用记录待执行、成功、跳过、拒绝或失败，以及尝试次数和耗时。

## 动态重规划

编排层不会把模型首轮计划当成不可修改的指令。每次工具执行后先进入验真：

1. 工具临时失败时，保持用户所选主模型和原业务目标，最多重试三次。
2. 财务、任务阻塞等必需证据缺失时，根据验真器返回的 `requiredTools` 生成补查计划。
3. 规划模型多选但与当前目标无关、参数不成立的工具会标记为 `skipped`，不会被当成执行故障。
4. 三轮后仍缺少必要证据时，本轮进入 `needs_input` 或 `failed`，禁止把模型猜测包装成业务事实。

主 `AliceAgent` 与兼容聊天链路必须执行同一重规划约束：

- 编排层根据整句话独立判定财务、任务、画像、附件、产品说明或写入意图，不再根据“模型已经调了什么工具”反推意图。
- 金额、产品说明、需求人画像、附件、单任务和跨任务均有必需的确定性工具；模型漏调时由编排层补齐。
- 补查参数使用纯程序实体解析：明确任务 ID 和会话引用优先，否则从句子中提取任务标题或需求人姓名。
- 补查成功后，主模型只能基于确定性证据重写答案；重写失败时不恢复使用未验证初稿。
- 已失败工具后续成功补查时，本轮以最终成功证据为准；同一工具最多尝试三次。

## 复合目标拆解

用户不需要把一个需求拆成多轮提问。编排层会从整句话中识别多个并列目标，例如“核对本月金额、列出延期任务、说明怎么下载回单”，并分别建立验真要求：

- 每个目标独立匹配必需工具，不能因为财务目标已经查到数据，就跳过任务或产品说明目标。
- 同一轮动态重规划会合并缺失工具，避免为三个目标重复调用已经成功的工具。
- 最终整理器收到明确的目标清单和全部确定性证据，必须逐项回答；任一目标缺少证据时只说明该项缺失，不用猜测填空。
- 写入与查询可以出现在同一句中：写入仍生成确认卡，查询部分仍需读取真实数据，二者互不替代。
- `verification.detectedIntents` 会进入运行审计，便于定位模型是否遗漏了用户的某一项要求。

复合目标的工具参数不能直接复用整句。`agentEntityResolver` 会先按标点和“再、同时、另外、然后”等连接词切分目标，再为每个工具选择自己的问题片段：财务工具只接收金额工时片段，产品知识只接收使用问题，附件搜索只接收文件片段，任务与画像工具再从对应片段提取任务标题或姓名。这样可以避免把“分析陈义君”当成人名，或把“验收附件，并告诉我状态”拼进任务标题。

## 会话级任务引用

- 模型或用户通过消歧卡明确选中任务后，`AliceAgentState.taskReference` 保存 `taskId + title`，该状态与会话 Durable Object 同步持久化。
- 后续“这个 / 那个 / 刚才 / 上述 / 继续 / 它”等指代会由编排层补入已确认 `taskId`，不依赖模型凭对话文本重新猜标题。
- 新的明确任务 ID 会替换旧引用；清空对话时引用一并清除，不跨会话串用。

## 模型与 Runtime

自动模式、工作助手手选云模型和本机 CLI 必须服从同一套 AgentTurn、工具注册表、权限与验真规则。模型只是可替换的推理适配器：

- 用户手选模型在正常情况下始终是本轮主模型。
- 主模型先按同模型策略完成重试和结构修复。
- 只有超时、额度、鉴权、供应商故障或多次无效结构等极端失败，才启用备用模型。
- 备用模型切换必须在运行记录中标注实际模型与原因，不能静默掩盖主模型故障。
- 本机 CLI 不持有 D1/R2 凭证，只能使用当前网页会话签发的短期、只读、租户受限工具。

## 权限与租户隔离

`src/agentScope.ts` 为内部工具调用生成 HMAC 签名上下文：

- `workspaceId`
- `principalId`
- `role`
- `runId`

Worker 会同时校验内部密钥、签名和工具权限。仅修改工作区 Header 而不重新签名会被拒绝。任务、附件、财务、会话、计划和任务记忆都必须使用该工作区过滤。

附件源文件和预览不接受“猜 ID 即读取”：登录主体或签名系统任务必须与附件任务属于同一工作区，公开分享 token 也必须和任务工作区一致且快照确实包含该任务。确认凭证同时绑定工作区与发起主体，Workflow 只能在保留这两个字段后执行。完整攻击矩阵见 [`AGENT_TENANT_SECURITY.md`](./AGENT_TENANT_SECURITY.md)。

角色规则：

- `admin` / `collaborator`：可读；写入仍必须先预览再确认。
- `viewer` / `mcp-read`：只读。
- `client`：只读允许范围内的任务和附件，不开放管理员财务工具。
- `guest`：仅产品说明与公开能力上下文。

Alice 构建模型工具列表时会先按上述角色裁剪，Worker 再做服务端授权。签名执行和内部 Workflow 工具永远不进入模型工具列表。

## 提示注入边界

用户消息、任务字段、附件文本、工具结果与额外上下文均按不可信数据处理。系统会清理伪造角色标记和上下文闭合标记，并明确要求模型不得执行数据中的权限变更、密钥请求或免确认写入。该层只负责降低模型受诱导概率；真正的安全边界仍是角色工具裁剪、Worker 权限、租户 SQL 过滤、签名确认凭证与确定性事实验真。

## 验真规则

- 金额、工资、计费工时必须来自财务计算工具，不允许模型自行重算。
- 具体任务卡点、延期、等待原因必须读取任务详情和有效等待记录。
- “哪些 / 所有 / 全部”跨任务问题必须调用 `query_task_portfolio`，由 Worker 在当前工作区内确定性计算状态、逾期、正在等待、负责人和最近进展；不允许用标题关键词搜索代替全量聚合。
- 附件存在性、名称、类型和地址必须来自附件工具。
- 工具返回多个相似任务时必须让用户选择。
- 任务型工具必须返回可核对的 `taskId`；请求 ID 与返回 ID 不一致时，该证据立即降级并停止采用。
- 已验收 / 终止 / 不计费任务不得同时返回活动等待；活动等待必须具有原因或备注以及开始时间。
- 业务事实没有确定性证据时不得输出肯定结论。
- 写入必须经过预览、签名确认凭证、人工确认和幂等执行。

模型若漏掉必需工具，编排层会补查；模型回答与工具证据冲突时，工具事实优先，并记录一次验真纠正。

业务工具全部成功也不能直接采用主模型初稿。`agentFactGuard` 会从确定性证据建立带来源和字段路径的结构化声明，再由程序为每个工具生成权威事实区块。AliceAgent、Worker 兼容聊天、本机 CLI 回接和确定性阻塞兜底共用该协议；模型负责理解与规划，不再自由改写金额、工时、百分比、日期、状态、任务 ID、名称、等待原因和任务/附件数量。最终答案必须完整包含每个工具的事实区块，缺少来源或出现证据外关键值时停止采用。

确定性编排单测使用 `npm run agent:orchestrator:test`，当前 40 条断言覆盖意图路由、复合目标、目标分句、工具参数作用域、实体清洗、部分目标已验真、写入预览确认、漏调工具、非确定证据、首次失败后成功与三次上限。

最终答案事实保护使用 `npm run agent:fact:test`，当前 45 条断言覆盖阿拉伯数字与中文数字错误、来源区块缺失、AliceAgent/旧 Worker 两种工具结构、结算回单、任务记忆和持续计划。`npm run agent:fact:production` 会读取正式健康接口，确认生产 Worker 已拒绝合成错误事实；该检查属于正式部署命令的强制步骤。

## 执行审计

每轮执行会写入 `agent_turn_runs`，并在「设置 → 模型 → AI 运行中心」展示。审计只保存：工作区、主体、Runtime、模型、意图、工具名与状态、证据来源、验真结果、尝试次数、耗时和备用模型原因；不保存用户问题、回答正文或模型隐藏思维链。自动化评测记录独立标记，不进入真实运营统计。

## 多租户开放门槛

正式开放注册前至少满足：

1. Agent 所有业务工具都有工作区过滤回归。
2. 会话、计划、记忆、后台任务和模型配置全部租户化。
3. 跨租户 ID、标题模糊搜索、附件路径和确认凭证均无法越权。
4. 所有写入工具均有人审确认、审计记录和幂等保护。
5. 主模型故障、工具超时、证据不足和备用模型切换均有可观测记录。
6. 关键业务问题有隔离评测和浏览器回归，不依赖人工碰运气发现。
