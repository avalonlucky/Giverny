# Agent 编排主链替换决策

> 状态：已采用（LangGraph 混合架构）

## 决策

放弃两代不能作为最终产品的主链：

1. Alice 内部固定模型 + 全量工具 + `toolChoice:auto`。
2. 每次请求固定串行“Director 分类 -> Planner 选工具”，再用关键词修补遗漏。

新主链使用 `@langchain/langgraph/web` 建立回合级状态图。Cloudflare Agents 继续负责 Durable Object 会话与待确认状态，D1/R2 继续是权威数据源，Workflow 继续是持久写入执行器。不引入 LangSmith Agent Server，不将租户数据和执行权限交给外部编排服务。

## 放弃旧方案的原因

1. 网站选择的主模型与 Alice 内部模型不一致，用户选择没有真正控制 Agent 的脑。
2. 模型一次看到大量工具，意图与工具选择纠缠在同一步；首步误选产品检索后，后续验真会沿错路继续。
3. 产品手册、快捷键和更新日志默认可见，导致普通业务命令被不相关知识污染。
4. 每次为一句新问法添加关键词例外，无法形成可扩展的产品级 Agent。
5. 127 条旧单轮评测中 123 条主要验收“是否命中指定工具”，不能证明用户的事情真的办成了。
6. 普通明确指令也要两次模型调用，首个可用结果慢，且容易被无关产品知识带偏。

## 新主链

1. `understand`：用户选择的主模型理解完整目标，不预取任务、金额或产品知识。
2. `shortlist`：程序根据语义决策、角色和风险从注册表缩选能力。
3. `direct_authorize`：单一、明确的指令由主模型在首次理解时同时给出最小动作，通过 Policy Validator 后直接执行，全回合只需一次规划模型调用。
4. `plan_node`：只有复合目标、对象不明确、先查后做或直接方案被策略拒绝时，才进入第二次计划。
5. `authorize`：独立校验能力名、Zod schema、角色、知识检索资格与 preview/execute 边界。
6. `finish`：将通过授权的计划交给 Alice 执行，或返回明确的缺失信息。
7. D1/R2 工具结果继续经过结构化事实验真；写入继续执行 preview -> 人工确认 -> Workflow -> 独立后置验收。

## 双图生产力闭环

回合不在“选出工具”时结束。第一张 `agentRuntimeGraph` 负责理解、缩选、计划和授权；第二张 `agentProductivityGraph` 负责将计划真正执行到可验收的终止状态：

```text
execute -> observe -> complete
                  -> needs_input
                  -> replan -> execute -> observe
                  -> failed
```

- `execute`：依次执行通过授权的能力，保留前序证据供后续工具绑定任务。
- `observe`：将工具返回转换为带来源、任务归属和确定性的证据，由业务规则校验目标是否真正完成。
- `replan`：只针对验真器指明的缺口补充最小读取能力；无法安全推导参数时转为 `needs_input`，不猜测对象。
- `complete/needs_input/failed`：每轮必须以三种状态之一结束，禁止停在模糊的“正在重规划”。
- 硬预算：最多 3 轮、8 次工具调用；超限转为 `failed`，不无限循环。

主模型负责理解与首次计划，程序负责执行与计算，业务规则负责验收和安全约束，LangGraph 负责组织状态转移。这些确定性规则是保险层，不再代替主模型做首轮意图路由。

## 生产力验收标准

- “帮我新建一个任务”等明确命令必须在一次主模型调用后进入创建预览或返回确切缺失字段。
- 未询问产品使用、设置、快捷键、更新日志或品牌故事时，不得调用产品知识检索。
- 评测同时检查任务是否完成、是否有首个可用结果、是否乱检索、模型调用预算和写后验收，不再只检查工具名。
- 生产回包记录 `orchestration.engine/path/modelCalls`，便于定位是理解、策略、计划还是执行出了问题。

## 依赖与体积决策

LangGraph 子图的浏览器/Worker 压缩包当前约 1.16 MB，主要来自 LangChain Core、Zod 和 LangSmith 客户端依赖。架构守卫以 1.3 MB 为硬上限；超限必须裁剪依赖或重新评估，不得无声增长。

## 知识检索边界

- `search_product_help` 和 `get_giverny_context` 只在 Director 明确设置 `requiresProductKnowledge=true` 时进入候选集。
- `search_workspace` 只在用户明确要求跨任务、附件、对话或知识的全域搜索时可用。
- 个人知识笔记与联网搜索均需用户明确表达，不再默认预取。

## 不变的边界

- 不修改金额、工时、验收日期、完成日期、补录映射或结算公式。
- 不降级租户隔离、确认凭证、审计、幂等与写后验真。
- 备用模型仍只能在主模型同模型重试失败且符合应急规则时启用。
