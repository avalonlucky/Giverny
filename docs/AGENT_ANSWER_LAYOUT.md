# 工作助手回答排版规范

本文是工作助手（Google ADK 主链）所有文本回答的统一排版规范。它约束的是**答案的结构与取值格式**，不约束答案的内容判断——内容仍由证据与审核决定。

规范按**数据形状**分类，不按业务领域分类。按领域分类会写成一堆特例，遇到没见过的问题就没有依据；按形状分类才能覆盖全部回答。

前台渲染：`react-markdown` + `remark-gfm`（`src/components/ChatContent.tsx`）。加粗、有序/无序列表、表格、删除线均可用；表格有独立样式与横向滚动（`.chat-markdown-table-wrap`，`min-width: 520px`）。

## 1. 通用规则（所有回答一律遵守）

1. **结论先行。** 第一句直接回答用户问的那件事，不做铺垫、不复述问题。
2. **关键值加粗。** 版本号、文件名、日期、金额、工时、状态各加粗一次即可，不要整句加粗。
3. **不使用 Markdown 标题。** 对话气泡里 `#`/`##` 过重，需要分节时用一行短加粗文字。
4. **一句话能说清就只回一句话。** 简单答案不套小标题、不套列表、不加"总结"。
5. **不解释过程。** 查了哪些工具、经过几个环节，属于执行过程面板，不进答案正文。
6. **不输出代码块**，除非用户要的就是代码或命令。
7. **同一条回答里，同类值的格式必须一致。** 不允许一处写「8月10日」另一处写「2026/08/10」。

## 2. 形状 → 结构（决策表）

| 数据形状 | 结构 |
|---|---|
| 单个值 | 一句话，值加粗 |
| 2 项同结构数据 | 一句话或两行短句，不用表格 |
| 3 项以上同结构数据 | 表格，最多四列 |
| 有先后顺序的操作 | 有序列表 |
| 无先后顺序的并列要点 | 无序列表 |
| 多维度且互相冲突 | 每个维度一行：`**维度**：值`，冲突写进同一行 |
| 层级关系（父任务/子项） | 两级无序列表，不超过两级 |
| 长文本（说明、纪要） | 分段落，段间空行，不强行列表化 |

表格要求：表头用简短中文；只放用户问到的列；不要为了填满而增列；数值列右侧不加单位重复（单位写进表头，如「工时（小时）」）。

## 3. 取值格式（与站内显示一致）

Agent 的文字必须和界面显示同一格式，用户才能交叉核对。

| 值 | 格式 | 站内来源 |
|---|---|---|
| 金额 | `1,234.5` + `元`，千分位，最多两位小数，不补零 | `formatYuan`（`src/lib/money.ts`） |
| 工时 | `3 小时` / `3 小时 20 分钟` / `45 分钟`，数字与单位间有空格 | `formatDurationZh`（`src/lib/dateTime.ts`） |
| 月份 | `2026 年 8 月` | `monthLabelCn`（`src/worker.ts`） |
| 日期 | `2026/08/10` | `formatPlanDateTime` |
| 日期时间 | `2026/08/10 16:14`；同一年内可用 `08/10 16:14` | `formatMonthDayTime` |
| 任务标识 | 任务标题加粗，`#` 加编号紧随其后 | 站内任务卡 |
| 文件 | 完整文件名含扩展名，加粗 | 附件列表 |
| 百分比 | 整数百分比，`38%`；不足 1% 写 `<1%` | — |

## 4. 各类回答的模板

以下按用户提问类型给出结构，取值格式一律按第 3 节。

### 4.1 直接事实（单值查询）

> 任务 **公司产品封套修改**（#1783086443320）最新的输出版本是 **硬封套V1.0B10.pdf**，于 **2026/08/10 16:14** 上传。

一句话结束。不要追加不问自答的版本历史。

### 4.2 序列与时间线（版本演进、进展、月度趋势）

结论一句话，再给表格。序列按时间正序，最新一行在备注列标注「最新」。

> 最新版本是 **V1.0B10**（**2026/08/10** 上传）。
>
> | 版本 | 上传日期 | 备注 |
> |---|---|---|
> | V1.0B06 | 2026/07/03 | |
> | V1.0B10 | 2026/08/10 | 最新 |

### 4.3 清单（任务、附件、日程）

超过三项用表格，列出用户问到的维度即可。清单前先给一句总数结论。

> 本月有 **4 个**任务处于进行中。
>
> | 任务 | 状态 | 交付日期 |
> |---|---|---|

### 4.4 数值汇总（财务、工时）

先给合计，再给构成。金额与工时按第 3 节格式。不要把合计和构成混在一段里。

> 2026 年 8 月已结算 **12,480 元**，累计 **86 小时**。
>
> | 项目 | 金额（元） | 工时（小时） |
> |---|---|---|

### 4.5 对比（跨对象、跨月）

用表格，被比较的对象各占一列或各占一行，保持一致；差值单独一列。

### 4.6 产品使用说明

用有序列表给步骤，每步一个动作。界面位置用 `设置 → 外观 → 吉维尼模式` 这种箭头路径，不加引号。

### 4.7 联网检索结果

每条结论后紧跟来源链接。没有来源的内容不要写进答案。

### 4.8 操作预览

一句话说明将要发生什么，再列出草稿里的关键字段。不要重复确认卡里已经显示的内容，也不要替用户补没提供的字段。

### 4.9 需要澄清

说明为什么不能唯一确定，然后**列出候选项**让用户挑，而不是只让用户"补充更准确的名称"。候选项超过三个用表格。

### 4.10 未通过证据校验

说明哪一条结论没能核实，不要输出未核实的内容本身。已核实的部分可以照常给出。

## 5. 明确禁止

- 复述用户的问题当开头。
- 「以下是…」「希望这对你有帮助」这类填充句。
- 用户没问的内部处理状态（附件分析进度、队列状态、`dead_letter`、重试次数、索引状态）。
- 证据只覆盖部分对象时使用「均」「全部」「三个都」这类总括表述。
- 同一条回答里混用两种日期或金额格式。
- 为了排版而排版：两项数据套表格、一句话答案套小标题。

## 6. 规范落地位置

- 操作性规则写在 `agent-runtime/app/agents.py` 的 `COORDINATOR_INSTRUCTION` 里，因为只有提示词能被模型看到。
- 本文是完整规范与范例，供人评审；`scripts/check-google-adk-architecture.mjs` 校验两者不漂移。
- 澄清与未通过校验两类回答的兜底文案写在 `agent-runtime/app/runtime.py` 里，修改时同样遵守本文。
