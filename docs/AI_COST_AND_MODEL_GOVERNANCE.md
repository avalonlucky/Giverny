# AI 费用审批与模型一致性红线

本文是 Giverny 所有 AI 编码助手、部署人员和运行时实现共同遵守的强制规范。聊天中的临时说明不能替代本文。

## 1. 费用审批

任何可能产生、扩大或重复产生第三方费用的操作，执行前都必须取得项目所有者的明确同意。范围包括：

- Google Cloud Run 部署、扩容、创建服务或其他付费资源；
- 连接真实 Gemini、DeepSeek、OpenAI 等供应商的回归、评测或调试；
- 批量、并发、循环或多 Agent 扇出调用；
- 调整账单、预算、配额、付费套餐或自动扩缩容；
- 会让失败重试继续消耗 Token 的超时、重试和补偿任务。

审批请求必须先说明：供应商、具体操作、最大请求/模型调用次数、最大 Token 或资源范围、预计费用和停止条件。未得到本轮明确批准时，只能执行本地静态检查、Mock、隔离数据或不连接付费供应商的测试。不得把“继续”“修复”“发布收尾”解释为付费授权，也不得先产生费用再补报。

## 2. Google ADK 模型一致性

设置页/工作助手选择是本轮唯一模型来源：

1. Worker 把精确 `provider + model + baseUrl` 传给 ADK；API Key 只在 Worker 与受鉴权的 ADK 请求内短暂存在，不写日志、不进回包。
2. Scope Supervisor、Root Coordinator、所有专家与 Evidence Auditor 必须使用同一个所选模型；JSON 协议整理使用本地强类型解析，不得暗中调用另一模型修复。
3. ADK 回包必须声明实际 `provider/model`；Worker 同时核对最终模型、编排模型和 Auditor 模型。
4. 任一字段缺失或不一致，立即失败关闭；不得使用固定 Gemini、备用模型、低价模型或其他供应商代答。
5. 所选模型不支持 ADK 工具/结构化输出，或 API Key/Base URL 不可用时，向用户说明配置问题并停止，不允许静默切换。
6. 每个外层聊天请求最多执行 7 次模型调用：Scope Supervisor 最多 2 次（仅允许一次只读对象取证）、Coordinator 与专家合计 4 次、Evidence Auditor 1 次。Runtime 必须在回包中声明 `modelCallLimit: 7`，Worker 缺少该声明时阻止答案。禁止使用 Google ADK 默认的 500 次上限。
7. 用户界面的“模型推理”只能来自所选模型实际返回的 thought/reasoning 字段；工具调用、对象解析和审核状态必须单列为“执行过程”，禁止用定时器、模板文案或阶段提示伪造思考链。

## 3. 回归与发布

- 日常验证默认只运行静态架构守卫、Python 单元测试和 Mock/隔离评测。
- 真实供应商语义回归必须单独列出调用预算并取得明确批准；外层请求数量不能替代内部模型调用上限。
- 502/504 不代表没有费用。模型调用一旦完成，即使外层请求失败也可能计费，因此测试必须在调用前设置硬上限并在失败后立即停止。
- Worker 正式发布和任何付费基础设施变更同样需要明确批准；批准范围不自动延续到下一轮部署。现有 DMIT 套餐内的 Runtime 代码更新可以在用户明确要求部署时执行，但不得擅自升级 VPS 套餐或创建新付费资源。
- 生产 ADK Runtime 位于现有 DMIT VPS，Google Cloud Run 与 Gemini 不得作为隐藏生产依赖。Runtime 固定单进程、900MB 内存软限、1.2GB 硬限；VPS 扩容或新增实例前需要新的费用审批。

## 4. 事故处理

发现意外费用或模型不一致时，立即停止调用并保存脱敏证据：时间范围、外层请求数、内部调用数、实际 provider/model、部署版本和错误状态。禁止为“确认是否修好”继续向真实供应商重复请求；先完成本地修复和 Mock 回归，再申请一次受限真实验证。
