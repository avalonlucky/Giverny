# Giverny 品牌产品片 V2 · 65 秒逐镜分镜

**这支片子要告诉公司、兼职团队、设计服务负责人和独立创作者：Giverny 把原本分散、容易消失的工作投入，变成一条看得见、说得清、结得明白的成果链路，同时让可靠的工作工具保留艺术与生长的温度。**

## 提案总览

| 镜头 | 节拍 | 时长 | 画面 | 为什么存在 |
| --- | --- | ---: | --- | --- |
| 01 · 投入正在消失 | 痛点 / Hook | 8s | 聊天、表格、文件三个工作碎片分散，随后切入真实 demo 工作台的空白搜索与任务入口 | 先讲观众正在承受的问题，而不是先介绍产品名称 |
| 02 · Giverny 的理由 | 品牌 / Value | 7s | 登录页莫奈花园缓慢显现，水面光线收束成 Giverny 标志，再过渡到纸张式产品界面 | 解释品牌不是装饰：工具也可以保留艺术和生长感 |
| 03 · 一项工作如何生长 | 产品证据 1 | 11s | 真实新建任务 → 打开任务 → 记录进展 → 添加实际工时 → 附件进入任务时间线 | 用一条完整真实路径证明“工作开始留下证据” |
| 04 · 验收成为边界 | 产品证据 2 | 9s | 打开验收终审，逐项扫过进度、分段工时、附件和备注，确认后状态到 100% | 证明 Giverny 不只记录过程，还建立了进入结算的可信边界 |

**长度依据：** 七个镜头中，五个承担叙事或真实产品证据。65 秒允许每个真实操作停留 6–11 秒，观众能够看懂操作对象与结果，不再像 20 秒版本那样把多个卖点挤在同一画面。

**节奏：** `慢建立 → 慢揭示 → 中速连续操作 → 停顿核对 → 清晰释放 → Agent 高点 → 慢收束`。

**转场语言：** 60–70% 使用编辑式水平推页；品牌进入产品使用一次轻柔 focus pull；Agent 高点使用一次克制的水波形变；结尾使用慢速模糊交叠。不会每个镜头换一种转场。

## 镜头 01 · 投入正在消失（00:00–00:08）

### 体验

观众先看到的不是产品，而是熟悉的工作现实：一句需求停在聊天记录里，一段时间孤零零地躺在表格中，一个“最终版”文件被推入没有上下文的文件夹。三个碎片都是真的工作，却彼此无法证明对方。

### 画面

- BG：暖白纸面，极轻的水面纹理，只用于建立 Giverny 的视觉温度。
- MG：三个不等宽工作碎片，分别只显示“需求”“实际 2.5h”“最终稿”，不仿制微信或其他品牌界面。
- FG：短句“真实投入，不该消失。”位于左下安全区，不覆盖碎片内容。
- 结尾 1.5 秒：碎片之间出现断裂的细线；真实 demo 工作台从右侧进入，成为下一镜的承接面。

### 动作

需求碎片停顿，工时碎片错位，文件碎片向远处滑走；三者不做花哨翻转。断裂线只绘制一次。真实工作台以稳定水平推页接管画面。

### 声音

三个轻微、不同质感的提示音；文件滑走后留下短暂安静。旁白说到“最难说清”时音乐第一次落下低音。

### 转场

编辑式水平推页，0.45s，速度连续；不使用故障、粒子或闪白。

## 镜头 02 · Giverny 的理由（00:08–00:15）

### 体验

真实工作台暂时退入纸面，莫奈花园的光从背景透出。这里不是突然插入一张艺术图，而是在解释：为什么严谨的任务与结算工具，会叫 Giverny。

### 画面

- BG：正式登录页使用的花园图，保持原有水面、树影和低饱和色彩。
- MG：Giverny 标志与一句品牌解释；不要出现多张花、花瓣或装饰睡莲。
- FG：屏幕短句“可靠的工具，也可以保留艺术。”
- 花园右侧保留一小块真实产品纸面，让艺术与工具同时存在，而不是互相替代。

### 动作

花园只做一次缓慢横移，水面出现一圈真实、克制的涟漪。涟漪边缘变成产品界面的发丝线，镜头沿着这条线进入任务创建。

### 声音

音乐增加温暖和声；Logo 出现时只有一个轻音，不做“品牌爆炸”。

### 转场

Focus pull，0.65s：花园稍微失焦，真实新建任务界面获得焦点。

## 镜头 03 · 一项工作如何生长（00:15–00:26）

### 体验

这是全片第一个核心证明镜头。观众跟着一次真实操作，看见任务不是一个标题，而是需求、进展、实际时间和文件共同生长出来的工作记录。

### 真实操作顺序

1. 在 demo 空间点击“新建任务”。
2. 选择一条适合展示的虚构岗位任务，例如 UI 设计或产品经理任务。
3. 填写简短需求与交付时间，保存。
4. 打开刚创建的任务，在右侧记录一条进展。
5. 添加一段实际工时。
6. 添加或展示一份 demo 附件进入任务时间线。

### 画面

- UI 始终占画面 82–92%。
- 摄像机只跟随当前操作区域：新建表单 → 任务行 → 右侧时间线。
- 屏幕短句放在顶部留白：“需求 → 进展 → 实际工时 → 文件”。
- 不再额外绘制浮动指标卡，不让字幕盖住输入框、任务名或进展内容。

### 动作

真实鼠标与输入是主要动效。只增加一次轻微镜头推近和一次时间线发丝线延伸；附件缩略图使用产品自身的上传/完成状态，不重新绘制假动画。

### 声音

真实键入声降低到背景；保存任务、记录进展和附件完成各有一个克制确认音。

### 转场

任务时间线向下延伸并成为验收弹窗的左侧核对线，0.4s 编辑式推页。

## 镜头 04 · 验收成为边界（00:26–00:35）

### 体验

节奏放慢。观众能看清 Giverny 最重要的业务边界：不是点一下“完成”，而是把真实投入和交付依据重新核对后，才允许进入结算。

### 真实操作顺序

1. 使用 demo 中适合验收展示的虚构任务。
2. 打开交付验收终审。
3. 镜头依次落在当前进度、分段工时、验收附件和备注。
4. 展示确认后的 100% 与已验收状态；录制方式不得破坏需要保留的 demo 种子数据，可使用专用临时 demo 任务。

### 画面

- 验收弹窗接近满画面，背景工作台只作为上下文。
- 每次只强调一个核对区，其他区域轻微降权，但不模糊到不可读。
- 屏幕短句：“验收，是进入结算的边界。”

### 动作

核对区域按真实滚动顺序进入视野；工时合计保持稳定，不做夸张数字跳动。最终状态变化使用产品自身反馈，并留出 1 秒阅读。

### 声音

滚动无音效；确认验收时用一次低而稳的“落定”声，不用庆典音效。

### 转场

确认后的绿色状态面扩展为结算页的表头色，0.5s 形态承接。

## 镜头 05 · 从证据到对账（00:35–00:45）

### 体验

前面累积的任务、时间和文件不再只是后台记录，它们现在变成合作双方都能看懂的正式结果。这一镜直接回答产品最现实的卖点：为什么月底不用重新证明。

### 真实操作顺序

1. 打开 demo 结算页。
2. 切换到在线回单预览。
3. 展示任务、工时、金额和交付信息来自同一份回单。
4. 打开合作伙伴只读链接或分享预览。
5. 展示交付文件可查看，但没有后台编辑入口。

### 画面

- 结算回单先占据 88% 画面，随后以分屏保留在左侧，右侧打开只读分享页。
- 不叠加虚构总金额；只显示录制时 demo 页面真实数据。
- 屏幕短句使用四个直接问题：“做了什么 · 花了多久 · 交付了什么 · 为什么结算”。

### 动作

镜头从回单表头向任务明细平移，再跟随一次分享操作。分屏变化由真实窗口位置承接，不做 3D 飞卡。

### 声音

回单打开时是纸张展开声；分享页进入时用轻微空间打开声。

### 转场

分享页中的任务标题保持为视觉锚点，右侧爱丽丝面板从产品真实位置进入。

## 镜头 06 · Agent 在上下文里工作（00:45–00:55）

### 体验

这是全片能量最高点，但重点仍是“可靠”，不是“魔法”。爱丽丝读取真实 demo 上下文，给出可核对的结果，并在写入动作前停下来向用户确认。

### 建议演示任务

- 先问：“总结本月已经完成的工作，并指出需要关注的任务。”
- 展示执行链路读取任务、进展或文件依据。
- 再发起一个需要确认的动作，例如生成任务计划或创建草稿。
- 镜头停在确认卡，明确表现“写入前确认”。

### 画面

- Agent 面板使用真实产品 UI，占画面约 70%；左侧仍保留与回答对应的真实任务或文件上下文。
- 思考/执行链路按实际步骤出现，禁止剪成固定三步模板。
- 对结果中的任务名、数量或金额只使用真实 demo 返回值。
- 屏幕短句：“理解上下文 · 写入前确认 · 结果可验真”。

### 动作

主要动效来自产品真实流式执行；镜头只做一次从问题到事实结果的缓慢下移。确认卡出现后停留至少 1.2 秒。

### 声音

音乐加入轻微脉冲；每个真实执行节点只有极轻提示。确认卡出现时脉冲停止，让观众感到控制权回到人手里。

### 转场

一次克制的 ripple-waves 或 CSS ripple，0.7s。水波只用于把“可验证的结果”带回品牌花园，是全片唯一明显的品牌形变转场。

## 镜头 07 · 留下自己的风景（00:55–01:05）

### 体验

全片不再介绍新功能。工作台、任务时间线、交付文件与结算回单依次成为一条完整路径，然后安静退入花园。观众最终记住的不是菜单数量，而是“我的工作终于留下了完整的风景”。

### 画面

- 前 4 秒：四个真实产品画面按生命周期顺序平铺成一条连续带，不做等大卡片网格。
- 中间 2 秒：一条 sage 发丝线贯穿“需求 → 进展 → 验收 → 结算”。
- 后 4 秒：产品画面轻轻退开，登录页花园与 Giverny 标志出现。
- 最终 Slogan：“让创作在自己的花园里生长。”
- 右下角只保留 `mayeai.com` 与“演示空间 · 虚构数据”小字。

### 动作

产品带稳定向左移动；生命周期线绘制后停住。花园从纸面下方显现，不使用花瓣、粒子或 Logo 爆炸。最后 1.2 秒保持近乎静止。

### 声音

音乐回到开场和声，一次温暖的终止和弦，水声尾音延伸到最后一帧。

### 退出

最终场景允许在最后 0.4 秒轻微淡入暖白，不进入纯黑。

## 录制与数据纪律

- 只登录 `demo@mayeai.com`，始终确认侧栏显示“演示空间 · 虚构数据”。
- 不读取、不录制、不缓存正式工作区的金额、工时、文件或人员信息。
- 不在画面中出现登录密码、会话 Cookie、管理员邮箱或内部 Token。
- 需要写入演示数据时优先创建专用临时任务；拍摄完成后只清理本次明确创建的临时记录，不改动既有种子任务。
- Agent 画面必须使用真实响应，不能把预写文案伪装成模型输出。
- 国际版只替换旁白、字幕和宣传短句；产品 UI 如果仍为中文，应通过镜头与英文字幕解释，不伪造尚不存在的产品语言界面。

## 本轮审核问题

1. 核心命题是否准确：Giverny 的价值是让工作投入形成完整、可追溯、可结算的成果链路？
2. 品牌解释是否准确：艺术与花园是产品温度，不是覆盖业务信息的诗意包装？
3. Agent 定位是否准确：真实上下文、主动分析、写入确认、结果验真？
4. 65 秒长度与七镜结构是否符合你希望的宣传片体量？

只有这四点确认后，再进入录制与粗剪。
